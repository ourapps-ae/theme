# Source mapping

Reference revision: `19905b75dbea89fbfd424d67fe26c81aaed0e018`. Extracted from the `recipe/` folder of `ourapps-ae/OurPoker`; paths and line ranges are of the files there.

## Web

- `implementation/web/tokens.schema.json` <- new. Shape of the values in `web/src/style.css:1-12` (`:root` colours) and the `Theme` type in `web/src/background.ts:3-6`, extended with spacing, radii and a type scale read off the repeated values in `style.css` (paddings 4 to 24, radii 6 to 999, font sizes 11 to 36). Generated platform-neutral (`generated-platform`).
- `implementation/web/themes.json` <- `web/src/background.ts:8-11` (`casino`, `home` values) and `web/src/style.css:1-12`. `casino` is renamed `night` and `home` `lounge`; `--gold` is `primary`, `--felt` `table`, `--felt-edge` `tableEdge`, `--bg` `background`, `#1b1a17` (ink) `onPrimary`, `#f6f1e4` and `#c0262d` (card face and red, `style.css:121-122`, `ios Palette`) `paper` and `paperAccent`. The recipe's `felt` and `bg` differ between `style.css` and the per-room `Theme`; the per-room values are kept.
- `implementation/web/tokens.ts` <- new (`generated-platform`): validation, `resolveTheme` (settings `themeName`, `primaryColour`, `tableColour`), and the CSS, Swift and Kotlin renderers. `Theme.setTheme` in `web/src/background.ts:66-75` set `--felt` and `--bg` directly; `applyTheme` replaces it.
- `implementation/web/theme.css`, `implementation/apple/Sources/ThemeTokens.swift`, `implementation/android/src/main/java/ae/theme/ThemeTokens.kt` <- generated by `build-tokens.ts`; checked for drift in `tests/web.test.ts`.
- `implementation/web/build-tokens.ts` <- new command line wrapper.
- `implementation/web/background.ts` <- `web/src/background.ts:1-181`. Kept: the random generator (`19-22`), particle and speck seeds (`25-32`), the drawing (`109-181`) and placement formulas. Generalised: the `themes` and `scenes` tables and `./art/scene-<room>-*` file names (`8-17`, `53-61`) became the theme tokens and a caller-supplied `Scene` (`setScene`); suit characters (`24`) became the theme's `glyphs`; the placement maths (`150-180`) became pure `glyphFrame`, `speckFrame`, `flicker`, `figureBox`; the sprite tint and glow colours are parsed from token colours. Left behind: the room id and the `casino` fall-back.

## Apple

- `implementation/apple/Sources/ThemeTypes.swift` <- new (`generated-platform`): token structs and colour parsing. Replaces the `Theme` struct in `ios/OurPoker/Sources/PokerBackground.swift:5-24` and `Palette` in `ios/OurPoker/Sources/OurPokerApp.swift:125-135` (colours only).
- `implementation/apple/Sources/BackgroundMath.swift` <- `ios/OurPoker/Sources/PokerBackground.swift:68-105` (seeded particles and specks) and `161-216` (flicker and placement formulas as pure functions).
- `implementation/apple/Sources/ThemeBackgroundView.swift` <- `ios/OurPoker/Sources/PokerBackground.swift:26-66, 107-217`. Generalised: the room dictionary, `Art.image` bundle lookup, the Mac-only crop rule (`40-52`) and room names became a `BackgroundScene` the application fills in. Left behind: `themeFor(roomId)`, `SceneCrop`, `Art`.
- Layout (`ios/OurPoker/Sources/Layout.swift`) belongs to `table-layout`, not here.

## Android

- `implementation/android/src/main/java/ae/theme/ThemeTypes.kt` <- new (`generated-platform`), as the Swift types.
- `implementation/android/src/main/java/ae/theme/BackgroundMath.kt` <- `android/app/src/main/java/app/ourapps/ourpoker/ui/PokerBackground.kt:86-107` (seeds) and `140-165` (placement).
- `implementation/android/src/main/java/ae/theme/ThemeBackground.kt` <- `PokerBackground.kt:1-138`. Generalised: `THEMES`, `themeFor`, `sceneImage` by resource name and the `SCENES` table became `BackgroundScene`; `ComposeColours` is new. Left behind: `Layout.kt` (to `table-layout`).

`colourTable`, `accentColour`, `shellPalette` (web), `ThemeSet.accent` (Swift) and `ThemePalette` with `ThemeSet.palette()` (Kotlin) are new code (`generated-platform` for the native two); they have no recipe counterpart. The recipe builds its android palette and Apple tint by hand from the same colours.

## Tests

- `tests/web.test.ts`, `tests/make-fixtures.ts`, `tests/fixtures/background.json`, `tests/apple/main.swift`, `tests/android/Main.kt`, `tests/native.py`, `examples/consumer.ts` are new. Each platform keeps its own random generator (the recipe's did differ: web 32-bit generator, Swift 64-bit generator, Kotlin `java.util.Random`), so seeded particles differ per platform as before; the placement formulas are compared across platforms with explicit particles.
